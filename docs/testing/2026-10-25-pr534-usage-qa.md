## Isolation

Native tests use the development build with bundle identity
`com.coral.ASTRA.usageqa.20261025` and a separate store under
`~/Library/Application Support/ASTRA Usage QA 20261025/AstraDev`.
The QA build script retains bundle verification and changes only the app
identity, output paths and launch environment. Its `LSEnvironment` also pins
the isolated store when macOS relaunches the app. Updates are disabled.

Historical tasks and provider reports are synthetic. Imported workspaces live
under `/private/tmp/astra-pr534-usage-qa`; onboarding created the separate
`QA534 Disposable` workspace. Existing provider authentication is used in
place. No credentials are copied and all real requests use Ask with explicit
instructions against tools, file access or commands. Production data is not
used. Screenshots, fixtures, build logs and read-only SQLite snapshots are
retained under `/private/tmp/astra-pr534-usage-qa`.

The active/uncertain imported rows are fault fixtures, not live provider
executions. Automated tests additionally hold the real kernel lease and
exercise persisted uncertain receipts, verified stop proofs, active turn
requests and missing/corrupt receipts.

An initial real-provider attempt in the onboarding workspace stalled before
provider launch. A process sample located the wait in macOS directory
enumeration during workspace orientation. It was cancelled through the UI;
ASTRA retained its reservation while cleanup remained uncertain. The real
Codex test completed in an independent local `/tmp` workspace. This verifies
independent progress but does not claim to fix that filesystem wait.

## Findings and corrections

- Repair now borrows the execution owner's lease and refuses active requests,
  uncertain receipts or missing modern ownership evidence. It never writes the
  receipt, releases resources, restarts a provider or replenishes run limits.
- Failed runs with zero usage are not proof of prelaunch failure. The legacy
  exception is restricted to the explicit `workspaceNotFound` preflight reason.
- Checked arithmetic rejects negative, overflowing or inconsistent reports;
  duplicate identities and ambiguous timestamps cannot invent replay order.
- Missing split counters with a nonzero recorded total are incomplete evidence.
- Export completeness follows retained runs and usage evidence; incomplete
  imports retain that fact across reexport. A first-report baseline check also
  protects stores imported before this marker existed.
- Native imports perform the correction immediately. Each asynchronous startup
  pass owns a unique gate token, so an intervening import cannot be overwritten.
- The full suite caught a file-size budget violation and a fixture autosave
  timer surviving store deletion. Import bookkeeping moved into its focused
  companion; reopened test contexts disable autosave and retain explicit saves.

Findings were reproduced with regression tests. The independent reviewer
reviewed the fixes and reported no remaining actionable findings. Final-commit suite, build, hook and CI
results are recorded in the PR. Histories without sufficient evidence remain
unchanged rather than receiving an estimated correction.
