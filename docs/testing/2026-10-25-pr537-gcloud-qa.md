## Isolation and evidence

Native QA uses the development build with a separate bundle identity,
`com.coral.ASTRA.gcloudqa.20261025`, and a separate `AstraDev` store under
`ASTRA GCloud QA 20261025`. Its only workspace is `PR537 GCloud QA 20261025`.
The existing isolated Claude profile is reused in place; credentials are not
copied. All synthetic tasks use Ask and explicitly prohibit cloud operations
and tool use. Production ASTRA data is not opened or modified.

The installed Google Cloud SDK 561.0.0 runs with an empty, isolated
`CLOUDSDK_CONFIG`. A wrapper on this app's PATH can add a five-second delay,
remain silent past the 20-second deadline, or return a synthetic connection
error. Normal and delayed modes forward to the real installed CLI. These
faults are controlled fixtures, not claims of a live Google Cloud outage.
No Google Cloud account was signed in, no credentials were copied, and no
cloud resource was queried or changed.

Artifacts are retained in `/private/tmp/astra-pr537-gcloud-qa`, including
`probes.log`, native screenshots, build logs, and read-only store snapshots.
The build script differs from the repository script only in QA identity,
output paths, and launch environment; it still performs bundle verification.

## Issues found and corrected

- Imported invalid budgets could reach unsafe numeric conversions. Import and
  execution now reject nonfinite or out-of-range values before spawning.
- Cache identity and manifest conversion lost the admission policy. The whole
  probe contract now survives round trips and separates cached verdicts.
- A slow base probe could skip required contextual access. Such a check stays
  blocked until its workspace access can be checked.
- Credential refresh now uses main's `config-helper` expiry-only probe, with
  narrow recognition of explicit missing/expired credentials. Network failures
  remain distinct from a signed-out account.
- Repair verification now preserves the longer budget, including task-session
  expiry and ADC repairs, while still requiring a successful response.
- Native QA exposed a Sign in button for a synthetic network failure. Health
  repair selection now offers Check with the diagnostic for that state.
- Native QA exposed a stale lateral panel after closing Plugins. Closing
  Configure now explicitly triggers a new health scan; existing generation
  guards reject stale replies.

## Verification boundaries

Automated regressions cover timeout admission, strict defaults, invalid budgets,
cache order, manifest persistence, contextual authorization, credential versus
network failures, strict repair verification, and stale scan publication.
The independent agent reviewed the patch and its corrections. Full-suite,
verified build, hook, and CI results are recorded on the final PR commit;
earlier checks do not substitute for final-commit validation.

Successful Google Cloud credential refresh against a real signed-in account
was not tested: the isolated configuration intentionally has no credentials.
Successful semantic responses are covered by automated fixtures. The real
provider completion proves the launch path, not authenticated cloud access.
